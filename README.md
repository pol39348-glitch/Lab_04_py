## Числа Фибоначчи

В пакете реализованы две версии функции для вычисления `n`-го числа Фибоначчи. В последовательности используются значения `F(0) = 0` и `F(1) = 1`.

- `fibonacci_iterative(n)` вычисляет результат циклом.
- `fibonacci_recursive(n)` использует рекурсивные вызовы и сохраняет уже вычисленные значения, чтобы не вычислять их повторно.

Параметр `n` должен быть целым неотрицательным числом. Если передать отрицательное число, функция вызывает `ValueError`. Если передать значение другого типа, функция вызывает `TypeError`.

Итеративная версия занимает `O(n)` времени и `O(1)` дополнительной памяти. Рекурсивная версия с сохранением результатов занимает `O(n)` времени и `O(n)` памяти.

Рекурсивная функция использует стек вызовов Python. При достаточно большом `n` глубина рекурсии может превысить установленный Python предел и привести к `RecursionError`. Для больших значений следует использовать итеративную версию.

## Сортировки

Обе функции принимают список чисел и возвращают новый отсортированный список. Входной список остаётся без изменений. Реализации сортировок не используют `list.sort` или `sorted`.

Поддерживаются пустой список, список с одним элементом, дубликаты, отрицательные числа, а также уже отсортированные и обратные данные. Если передать объект, который не является списком, функция вызывает `TypeError`.

### Bubble sort

`bubble_sort(values)` сравнивает соседние элементы и меняет их местами, если они стоят в неправильном порядке. Если за проход обменов не было, сортировка останавливается досрочно.

- Средний и худший случаи: `O(n²)` времени.
- Лучший случай на уже отсортированном списке: `O(n)` времени благодаря досрочной остановке.
- Дополнительная память: `O(n)`, поскольку сортировка создаёт копию входного списка.

### Merge sort

`merge_sort(values)` разделяет список на части, сортирует их рекурсивно и объединяет отсортированные части.

- Лучший, средний и худший случаи: `O(n log n)` времени.
- Дополнительная память: `O(n)`.

## Стек

Класс `Stack` хранит элементы по принципу LIFO: последним добавляется и первым извлекается.

| Операция | Назначение | Сложность |
|---|---|---:|
| `push(item)` | Добавить элемент на вершину | `O(1)` |
| `pop()` | Удалить и вернуть верхний элемент | `O(1)` |
| `peek()` | Посмотреть верхний элемент без удаления | `O(1)` |
| `len(stack)` | Получить количество элементов | `O(1)` |
| `bool(stack)` | Проверить, что стек не пуст | `O(1)` |

Вызов `pop()` или `peek()` для пустого стека вызывает исключение `IndexError`.

## Генераторы тестовых наборов

Функция `make_dataset(size, kind="random", seed=None)` создаёт список заданного размера.

| Значение `kind` | Содержание |
|---|---|
| `random` | Случайные целые числа |
| `sorted` | Числа в возрастающем порядке |
| `reverse` | Числа в убывающем порядке |
| `nearly_sorted` | Почти отсортированный список с несколькими перестановками |
| `duplicates` | Список с большим количеством повторяющихся значений |

Параметр `seed` позволяет повторить генерацию. При одинаковых `size`, `kind` и `seed` функция возвращает одинаковый список. Для случайных наборов разные значения `seed` обычно дают разные результаты.

Размер должен быть целым неотрицательным числом. Неизвестный вид набора данных приводит к `ValueError`.

## Тесты

Тесты проверяют:

- обе реализации чисел Фибоначчи и отрицательный аргумент;
- сортировку пустого списка, списка с одним элементом, отсортированного и обратного списка, списка с дубликатами и отрицательными числами;
- совпадение результатов сортировок с ожидаемым результатом на нескольких случайных наборах;
- сохранение исходного списка и обработку неверного типа;
- операции стека и поведение `pop` и `peek` на пустом стеке;
- воспроизводимость генератора при одинаковом `seed` и различия для выбранных разных `seed`.

Запуск тестов из корневой папки проекта:

```bash
python -m unittest discover -s tests
```

## Benchmark

Программа benchmark сравнивает bubble sort и merge sort на наборах разного размера и типа. Для каждого сочетания алгоритма, размера и набора выполняется не менее пяти повторов. Результаты сохраняются в `benchmark.csv`.

Запуск из корневой папки проекта:

```bash
python -m lab4_algopack.benchmark
```

Для каждого повтора входные данные создаются до начала измерения. Время генерации не входит в результат. Алгоритм получает отдельную копию входного списка, поэтому каждый запуск работает с независимыми данными.

Проверяются размеры `100`, `1 000` и `10 000` и пять видов входных данных. Bubble sort запускается для размеров `100` и `1 000`. Для размера `10 000` его запуск пропускается, поскольку квадратичный алгоритм может выполняться слишком долго. Merge sort проверяется на всех трёх размерах.

В CSV для каждого запуска записаны алгоритм, вид данных, размер списка, количество повторов и среднее время. Ожидается, что время bubble sort быстро растёт с увеличением размера списка, примерно пропорционально `n²`. Время merge sort растёт медленнее — примерно пропорционально `n log n`. Фактические значения зависят от компьютера и версии Python.

Benchmark нельзя запускать много раз на одном изменяемом списке: алгоритм может изменить его состояние, и следующие измерения будут использовать другие входные данные. В этой работе сортировки возвращают новые списки, но для корректной методики benchmark всё равно передаёт отдельную копию на каждом повторе.
